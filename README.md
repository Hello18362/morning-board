# 晨间看板

纯静态中文页面：天气、当天课程、按课程汇总的物品、可编辑的临时待办。网页主体无需账号、服务器、密钥或构建工具。Windows 桌面直接显示需要额外的本机宿主，见下文。

## 文件说明

- `index.html`：四个看板区块，以及默认折叠的导入、语音和安装说明。
- `style.css`：手机优先布局、触控尺寸、深色模式和轻量动效。
- `app.js`：读取 JSON、按日期显示课程/物品、待办与本机存储、定位和天气请求。周次、日期、导入校验和播报稿生成函数独立可测。
- `excel-import.js`、`vendor/`：本机 Excel 识别与解析，含许可证。
- `data/config.json`：城市、坐标、周次参考和节次钟点对照。城市/坐标留空时，网页尝试请求设备定位。
- `data/schedule.json`：课程。当前为教学安排表中的整学期循环记录（29 条，第 5–17 周），按周次、单双周和星期筛选。
- `data/items.json`：每日物品、各课程教材和待核对提醒。
- `data/plan.json`：每周建议待办。临时添加项和勾选状态仅保存在当前浏览器的 localStorage。
- `manifest.webmanifest`、图标、`sw.js`：安装信息、图标和静态页面离线缓存。天气请求不缓存到离线应用壳；天气结果另在浏览器本机缓存 1 小时。

## 天气为什么需要定位/网络

网页**不能读取安卓系统天气应用内部的数据**。本页面使用浏览器定位取得经纬度，再向 Open-Meteo Forecast API 请求每日天气（`weather_code`、最高/最低温和降水概率）。API 不用密钥；如果定位被拒绝、网址不是安全来源，或网络无法连接 API，页面会说明对应原因并提供重试。它不会猜测或默认使用杭州等城市。

在 `data/config.json` 填入自己确认的城市及经纬度后，网页会跳过定位，直接按该坐标查询；不要填不确定的坐标。天气服务仅依据配置坐标或本次设备定位。

## 本地预览

不能双击 `index.html` 用 `file://` 作为完整运行方式，因为浏览器会限制 JSON、定位和离线应用功能。进入本目录后运行：

```sh
python -m http.server 8765
```

然后在这台电脑打开 `http://localhost:8765/`。localhost 是安全上下文，可用于本机定位测试。不要把电脑的 localhost 地址直接发给手机：手机上的 localhost 指手机本身；局域网 HTTP 地址也通常不能用于定位。

## 部署到 GitHub Pages，供安卓手机使用

1. 将本目录中的**全部文件**放进 GitHub 仓库。仓库可设为私有/公开视 Pages 方案而定；Pages 发布后会生成 HTTPS 地址。
2. 在仓库的 **Settings → Pages** 选择发布分支和目录（通常 `main` / `/(root)`），保存后等待发布完成。
3. 用安卓 Chrome 打开生成的 `https://…github.io/…/` 地址。允许该网站使用位置信息；如果之前拒绝过，在 Chrome 的网站设置中把“位置信息”改为允许，然后回到页面按“重新定位”/“重试天气”。
4. 首次打开需要网络以下载页面和 JSON。Chrome 菜单中选择“添加到主屏幕”或“安装应用”，之后可从桌面图标打开；课程、清单及本机待办可离线查看，天气需联网更新。

如果 HTTPS 页面仍不能出天气，先看天气卡片给出的具体提示：定位提示请检查 Chrome 网站定位权限及安卓系统定位开关；“无法连接天气服务”表示设备网络到 Open-Meteo 的连接失败，可切换 Wi-Fi/移动网络后重试。

## 修改个人数据

所有 JSON 用 UTF-8 保存，不需要改 JS：

- `config.json`：设置 `city`、`latitude`、`longitude`。如果继续用设备定位，城市留空、坐标写 `null`。`weekReference` 代表“某日是第几周”，修改后照此校准；已录入日期则优先按具体日期。
- `schedule.json`：每项包括日期或周几、课程名、起止时间、教室和教材映射所用的课程名。新学期可以录具体日期，也可使用循环周次字段。
- `items.json`：`daily` 是每天物品；`byCourse` 的键必须与课表 `course` 完全一致。勾选物品按日期存于本机。
- `plan.json`：`days` 中用 `YYYY-MM-DD` 作为键，最多显示 3 条建议。

## 日期与单双周函数示例

在 `app.js` 中 `semesterWeek(day, semesterStart)`、`weekForDay(day, config)`、`isInWeekRange(week, ranges)`、`isCourseOnDay(course, day, week)` 都是独立函数：

```js
semesterWeek("2026-09-08", "2026-09-01") // 2
weekForDay("2026-10-12", { weekReference: { date: "2026-10-12", week: 6 } }) // 6
isInWeekRange(3, "1-4,7-9") // true
isCourseOnDay({ weekday: 1, weeks: "1-16", weekType: "odd" }, "2026-10-12", 5) // true（周一，第5周）
```

调整日期时注意：系统日期决定首页显示哪一天。具体日期课表仅在 `config.json` 的 `scheduleDates` 已覆盖日期内才视为已录入。


## 导入：Excel / JSON 先预览，再替换

1. 打开“设置 → 导入课程、教材与待办”，点“选择 Excel / JSON 文件”。支持 `.xls`、`.xlsx`、`.json`。
2. 已适配本次教务系统的《教学安排表.xls》（文件实际为 GBK HTML）；真正二进制 XLS 和 XLSX 支持**行式模板**。不能保证任意学校的网格课表均可识别，未知格式会报错，不会假装成功。
3. 其他表格请先“下载 Excel 模板”：课程、教材、待办各一张工作表。每行一条数据；教材同一课程多本书可写多行，日常物品的课程填“每天”；待办日期使用 YYYY-MM-DD。
4. Excel 模板中课程的具体“日期”有值时按日期；否则填写星期、周次和单双周。填写完整开始/结束时间；也可只填节次，使用 config.json 的 `periodTimes`，未知节次显示“时间待确认”，不猜钟点。
5. 可在“数据类型”选择只导课程/教材/待办，其他已识别工作表跳过；默认自动识别会预览整个文件。**预览标为“替换”的部分才会替换**，课程数组是替换，不是追加。
6. 点“确认替换这些数据”才保存。取消、格式错误、日期/时间错误均不覆盖旧数据。Excel 最多 5 MB、12 张表、每表 5000 行和 100 列；JSON 最多 1 MB；预览最多 60 行，不截断实际导入。
7. 文件在当前设备本地解析，不上传；Excel 解析库随网页携带，不需要运行时访问 CDN。原 JSON 模板、粘贴与导出入口继续保留。

导入保存在本机 localStorage，同设备换浏览器也不会自动同步。“导出课程、物品与计划”仅包含这三部分，**不是完整设备备份**：不含临时待办、勾选状态、定位和语音设置。不要为更新版本清空站点数据。

### 已安装旧版本怎样更新课程

网页/桌面代码更新不会强制覆盖用户已有课表。旧安装保留手改 JSON，已有本机导入也优先于默认课表。请使用新版导入入口，选择本次随包提供的 `整学期课程更新.json`，预览 29 条课程后确认。该文件仅含课程，保留教材和待办。它已经带有核对过的白天钟点，即使旧 config.json 未包含节次对照，也可正确显示。

### 维护入口与测试示例

- `excel-import.js`：`parseWeeks` 解析周次/单双周；`parseRows` 解析行式模板；`parseHtml` 解析本次教务课表；`readFile` 识别 HTML 型 XLS 或交给本地 SheetJS 读取真实 Excel。
- `app.js`：`normalizeImport` 识别整包/单文件，`validateImport` 校验日期时间与结构，`initDataTools` 管理预览确认；`readJSON` 优先本机导入。
- `data/config.json` 的 `periodTimes` 为节次对照。第 9–10 节钟点未提供，默认课表用空 start/end 保留节次；确定钟点后可修改 JSON 或重新导入填写完整时间的表格。
- `vendor/`：SheetJS CE 0.20.3、本地许可证与来源/摘要记录。取得的是 `@e965/xlsx` 第三方 npm 再发布包，已核对包的 SHA-512；不是官方 CDN 直接下载，不声称为上游最新版。

```js
BoardExcel.parseWeeks("5-9 单") // { weeks: "5-9", weekType: "odd" }
BoardExcel.parseWeeks("14-16 双") // { weeks: "14-16", weekType: "even" }
BoardExcel.parseWeeks("1-8,10-16") // { weeks: "1-8,10-16", weekType: "all" }
weekForDay("2026-10-19", { weekReference: { date: "2026-10-12", week: 6 } }) // 7
isInWeekRange(9, "1-8,10-16") // false
```

## 语音：内容和音色都能先确认

- 默认播报：日期/周次、天气（最高/最低温与降水概率）、课程起止时间与教室、未勾选物品、未完成待办。可在“播报内容与音色”中取消任意部分；只播报当前页面已显示的待办建议和临时待办。
- “更新播报稿”生成当前文字预览，“试听音色”仅读一句测试文字。页面不自动播放；“语音播报”点击后才启动，再点击可停止。
- 中文音色由设备/浏览器语音引擎提供。默认优先本机中文音色，也可选择、试听其他中文音色；稍慢/正常/稍快三档语速。本机标记来自浏览器的 `localService`，并非本项目提供或下载音色。不同设备不能保证同一声音。
- 本项目不接付费语音 API、不保存密钥。浏览器报告为非本机的音色**可能依赖网络服务**，不应把它称为保证离线。没有中文音色、接口未暴露、引擎启动失败、音频或网络错误分别提示。
- 如果当前网页容器没有 `speechSynthesis`，网页代码不能自行补齐系统接口。可尝试在系统 Chrome 打开、检查安卓文字转语音的中文语言包和媒体音量；仍不能播放时可预览、复制播报稿。没有承诺所有安卓浏览器都能正常播出。
- 8 秒未收到开始事件会停止等待并提示；此检测不能判断扬声器音量，收到开始事件也不代表你一定听到了声音。

`buildSpeechText(data, sections)` 是独立文字生成函数；`speechSnapshot()` 获取当前可见数据和勾选状态；`initSpeech()` 负责音色加载、设置、本机接口事件和失败降级。播报前重新生成文字，未录入课表不会播成“今天没课”，没有天气不会播 `--` 度。

## 安装形式：应用窗口不是桌面小组件

- **安卓**：用系统 Chrome 打开 HTTPS 地址，菜单中选择“安装应用”或“添加到主屏幕”（菜单因浏览器而异）。当前得到入口图标，点击后打开看板；不是在手机桌面直接持续显示数据的小组件。
- **Windows 电脑**：用 Chrome/Edge 打开 HTTPS 地址，在浏览器菜单的应用/安装相关入口安装。得到独立应用窗口，可手动固定任务栏。这是网页安装形式；若要回到桌面就看到数据，使用下面的 Windows 桌面版，而不是浏览器安装按钮。
- 网页安装形式是 PWA，不是 APK/Windows EXE；新增的 Windows 桌面版是单独的 EXE 包。豆包不能替代浏览器或操作系统的安装和权限流程。添加到主屏幕和桌面常驻显示是不同需求。
- 安卓桌面小组件仍未实现。Windows 已增加独立桌面宿主，不把普通应用窗口称作桌面挂件。
- 版本更新使用新的离线缓存标识；重新联网打开可下载新页面，不需要清除 localStorage。首次加载离线缓存前仍需联网；天气获取仍需联网。

```json

  "schedule": [
    {"date":"2026-10-14","course":"课程名","weekday":3,"periods":"1-2","start":"08:20","end":"10:00","room":"教学楼101"}
```

## 播报稿函数示例

```js
buildSpeechText({
  date: "2026年10月13日，星期二，第6周双周",
  weather: { description: "晴", high: 23, low: 15, rain: "百分之20" },
  courses: [], courseStatus: "尚未录入当天课表",
  items: ["水杯"], todos: ["复习"], todoStatus: ""
}, { date: false, weather: true, courses: true, items: false, todos: false })
// 今日天气，晴，最高23度，最低15度，降水概率百分之20。尚未录入当天课表。
```

浏览器自动化测试只能验证语音 API 的状态处理和文字正确性；实际设备是否能出声、音色是否合意，需要在目标手机上试听确认。


## Windows：桌面直接显示，不再是入口图标

网页保持 HTML/CSS/原生 JavaScript。新增 `desktop/` 是 .NET Framework + 微软 WebView2 桌面宿主：窗口挂接在 Explorer 的桌面图标层中，没有浏览器地址栏或任务栏应用按钮。普通工作窗口在它上方，回到桌面即可查看；不会悬浮挡住其他软件。

### 用户操作

1. 下载并**完整解压**“晨间看板-电脑桌面版.zip”。
2. 双击 `Install.cmd`，只给当前用户安装到 `%LOCALAPPDATA%/MorningBoardDesktop/Program`，无需管理员权限。也可以直接运行 `MorningBoard.exe` 便携使用。
3. 回到桌面。按住看板顶部拖动位置；右上角“设置”或系统托盘菜单可锁定位置、刷新、隐藏、退出。
4. 主动勾选“登录后自动显示”，下次登录此 Windows 用户后显示。默认不开启，也不在登录屏幕/锁屏上显示。
5. 关闭：菜单退出。取消自启动：先取消该勾选，再退出。卸载：完成前述操作后删除 Program 文件夹；WebView2 文件夹是本机个人数据，想保留就不要删除。

首次安装仍需运行一次程序；它是后台运行的桌面挂件，不是把纯网页变成系统壁纸，也不保证每种 Windows 桌面环境兼容。看板覆盖的区域内桌面图标不能操作，可拖到空白区域。

### 文件与关键函数

- `desktop/DesktopBoard.cs`：桌面容器。`Native.FindDesktop()` 找桌面图标层；`Native.Attach()` 只将自己的窗口挂接进去；`ResizeBoard()` 限制大小并按尺寸切换显示布局；`DesktopContext` 管理托盘菜单和窗口恢复。
- `desktop/build.ps1`：用系统 .NET Framework 编译器打包；固定微软 WebView2 NuGet SDK 版本 `1.0.4258.31` 并验证 SHA-256，复制官方授权说明。网页文件用白名单复制，不包括 Git 仓库与下载缓存。
- `desktop/Install.cmd`：调用 EXE 的 `--install` 用户安装入口。升级时保留安装目录已有的 data JSON，不自动开启启动项。
- `desktop/使用说明.txt`：中文启动、定位、数据迁移、退出、卸载及限制说明。
- `desktop-view.css`：Windows 默认约 190×190 紧凑挂件；天气置顶，课程与待办并排，课程内显示教材。展开后显示日期导航、物品、更多待办、导入和播报设置。
- `desktop-view.js`：识别宿主标记，同步紧凑/展开布局，并在跨日时重读日期（有未提交输入时延后刷新）。普通网页与手机不启用。
- `app.js`、`sw.js`：桌面宿主直接读本机 app 文件，不注册离线 Service Worker，以免更新后读到旧副本；网页端继续保留离线缓存。

### 开发与自测试

需要 Windows 10/11 x64、.NET Framework 4.8、WebView2 Runtime。编译不要求安装完整 .NET SDK。首次编译需联网下载官方 NuGet SDK；后续可用本机缓存。

```powershell
.\desktop\build.ps1
# 输出在 desktop/build，默认不提交编译产物与下载缓存。
# 完整解压包中可执行隐藏自测试：不修改启动项、不操作其他软件。
.\MorningBoard.exe --self-test C:\path\desktop-result.json
```

宿主将 app 目录映射到本机虚拟 HTTPS 来源 `morning-board.local`，不启动 HTTP 后台服务器，不依赖 GitHub Pages 是否可访问。定位由用户点击后明确授权；天气仍走已有 Open-Meteo 请求，无法读取 Windows 天气应用内部数据。语音仍使用设备音色，不承诺所有环境能发声。

**数据隔离**：桌面 WebView2、浏览器、手机各有自己的本机存储，不自动同步。浏览器“导出课程、物品与计划”可在桌面重新导入，但不含临时待办、勾选、定位和语音设置。桌面数据在 `%LOCALAPPDATA%/MorningBoardDesktop/WebView2`，位置在 `window.json`，日志在 `desktop.log`。

**兼容性边界**：Explorer 图标层结构不是微软稳定公开的小组件 API。隐藏宿主测试能验证父窗口/子窗口样式、WebView2、本机 JSON、安全上下文和存储；不等于人工拖动、显示桌面、多屏、Explorer 重启或实际登录自启均已验证。失败时明确提示，不偷偷降级成普通 App。程序未签名，Windows 可能提示核实来源；不要全局关闭安全保护。

官方开发资料（实际下载核对）：
- Microsoft Learn：Working with local content in WebView2；SetParent (winuser.h)。
- NuGet：Microsoft.Web.WebView2 1.0.4258.31；包中 LICENSE.txt、NOTICE.txt 随发行包保留。


## 日期浏览、快捷待办与紧凑桌面布局

- 看板顶部可用“前一天 / 后一天”、日期选择器浏览课程；“今天”一键返回。
- 顶部日期、周次、课程、教材/物品、待办一起切换，天气仍为**今天**。未录入日期会提示未录入，不推测“没课”。
- 待办直接输入后按回车或点“添加”，无需导入 JSON；按当前所选日期保存。中文输入法确认选词不会提前添加。
- 勾选和临时待办按日期隔离，刷新后保留；未提交草稿只在当前页面会话内保留。
- Windows 桌面版默认约 190×190 像素（约 5×5 厘米，受 Windows 显示缩放影响）：天气置顶，课程与待办并排；课程行直接显示教材。紧凑态隐藏日期导航、物品清单和设置细节。
- 点击“展开”或拖动右下角“◢”放大后，才显示完整课程、物品、日期切换、待办编辑、导入和播报设置；放大状态可滚动。拖动窗口尺寸会自动切换紧凑/展开布局。
- 在顶部“设置 → 面板大小”选择紧凑/小/中/大，或拖动右下角自由缩放；松手保存大小和位置，下次启动恢复。“锁定位置和大小”同时阻止拖动和缩放。
- 已安装的旧版首次更新启动时会自动切换为紧凑尺寸并保留原桌面位置；之后用户手动选择的大小会继续保存。
- 网页更新不会自动替换已安装的 Windows 宿主。请先退出旧桌面版，再解压新版安装；安装保留已有 JSON 和本机网页数据。

### 本次改动的维护入口

- `index.html`：日期导航及待办输入表单；`style.css` / `desktop-view.css`：响应式排列，不固定卡片高度。
- `app.js`：`shiftDay(day, offset)` 独立处理日期偏移；`renderSelectedDay(day)` 重绘课程、物品和待办；`initTemporaryTodos()` 用单个表单提交入口处理回车和按钮，不叠加监听器。
- `desktop-view.js`：定时更新课程结束状态时核对所选日期，避免把明天的课标灰。
- `desktop/DesktopBoard.cs`：`ResizeBoard()` 限制并应用尺寸，`ChooseSize()` 处理尺寸预设，`SavePosition()` 把位置与大小保存到本机 `window.json`；旧位置文件没有宽高时沿用默认大小。
- `sw.js`：更新离线缓存版本，让旧网页获取新的资源。
